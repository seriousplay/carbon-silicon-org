# 新增工具 · 碳硅组织语言一致性审计与修正

> 审计日期：2026年7月26日
> 审计范围：9个拟新增工具
> 审计标准：与碳硅组织现有22工具 + 书籍12章框架的术语、隐喻、诊断逻辑一致

---

## 一、碳硅组织核心语言体系（审计基准）

### 1.1 核心隐喻域（不可与外部概念混用）

| 隐喻域 | 核心概念 | 禁忌 |
|:--|:--|:--|
| **大陆→海洋** | 大陆文明组织 / 海洋文明组织 / 物种迁徙 | 不要混入"数字化转型""敏捷组织"等泛咨询语言 |
| **三螺旋** | 结构层 / 细胞层 / 环境层 | 不要用"流程/文化/人才"等平面分类替代 |
| **智能密度** | 单位人可调用的智能资源 / 反馈速度 / 经验复用能力 | 不要简化为"效率"或"人效" |
| **碳硅共生** | 碳基判断 + 硅基执行 / 碳硅翻译力 | 不要用"人机协同"替代（碳硅强调共生而非工具关系） |
| **液态网络** | 任务单元 / 混合智能细胞 / 业务本体 / 四支柱 | 不要用"团队/部门/岗位"等固态组织语言 |

### 1.2 关键概念词典

| 碳硅标准用语 | 定义 | 不应使用的替代词 |
|:--|:--|:--|
| **任务单元** | 围绕一个业务闭环的最小生产单元（人+AI+数据+接口） | 岗位、角色、职责 |
| **混合智能细胞** | 稳定运行的人机任务单元 = 碳硅组织的最小生产单元 | 人机团队、AI增强团队 |
| **碳硅翻译力** | 把人的意图翻译为AI可执行的指令，把AI的产出翻译为人类可用的价值 | AI驾驭力、提示词工程 |
| **意义创造力** | 在AI赋能下创造独特人类价值（判断、连接、定义） | 高价值工作、人的不可替代性 |
| **驾驭工程** | 设计人+AI的工作环境，而非亲手执行任务 | 工作流设计、编排 |
| **验证回路** | 设定标准 → 运行 → 检查差距 → 修正 → 沉淀 的闭环 | 质量检查、审核、评估 |
| **业务本体** | 业务对象、规则、动作边界的形式化表达，让AI"读懂"业务 | 知识库、业务规则 |
| **火种** | 第一条能跑通的人机闭环链路，验证了组织愿意改变 | 试点、POC、Quick Win |
| **大陆物种** | 旧大陆范式下的组织特征（层级/审批/岗位边界） | 传统组织 |
| **海洋物种** | 按碳硅逻辑设计的原生组织（液态/闭环/智能密度） | AI原生组织（可以用，但优先用"海洋物种"） |

### 1.3 工具设计规范

| 维度 | 碳硅标准 | 反例 |
|:--|:--|:--|
| **命名公式** | `[碳硅核心概念] + [诊断/自检/定位/体检/孵化/重写/迁移]` | "XX扫描矩阵""XX价值评估" |
| **副标题公式** | `从 A 走向 B` 或 `把 X 翻译成 Y` 或 `找到 Z 的起点` | "帮助你快速识别优先级" |
| **Problem句式** | "组织以为……其实……" 的反直觉揭露 | "管理者面临XX挑战" |
| **Output** | 始终包含组织数据沉淀项 | 纯个人报告，无组织沉淀 |
| **Tags** | 用碳硅概念词（智能密度/碳硅翻译/任务单元/业务本体/意义/权力/信任） | 用商科/技术词（KPI/效率/Agent/编排） |

## 二、逐工具审计

### 2.1 P0-1：AI价值三路径定位卡

**严重问题**：整个框架来自《极简AI领导力》的"减/加/乘"模型，与碳硅的语言体系完全不兼容。

| 审计项 | 原设计（❌ 外来语） | 修正（✅ 碳硅语） | 理由 |
|:--|:--|:--|:--|
| 工具名 | AI价值三路径定位卡 | **超级个体智能密度三向定位** | "路径"与三条航线混淆；"智能密度"才是碳硅概念 |
| 核心框架 | 减法/加法/乘法 | **驾驭力方向 / 翻译力方向 / 意义创造方向** | 三条通路恰好对应碳硅超级个体三轴：减法=驾驭力（减少重复释放智能）、加法=翻译力（把新能力翻译进闭环）、乘法=意义创造（放大产出连接更大问题） |
| 任务列表 | 5-8项工作任务 | 5-8项**日常任务链** | 碳硅以"链路"为观察单位 |
| checklist名称 | subtraction/addition/multiplication | 分别叫 **重复释放检视 / 新域翻译检视 / 闭环放大检视** | 每个检视名自带碳硅的动作语义 |
| 报告标题 | "最强路径推荐" | "**当下最值得投智能密度的方向**" | 不叫"路径"，叫"方向" |
| 行动建议 | "本周行动" | "**两周火种实验**" | 碳硅最小行动单位是"火种"（带验证信号的实验） |

**修正后的 Purpose**：
> 不是学会更多工具，是找到投入智能密度最快产生回报的方向。三条方向对应超级个体三轴的落地：把重复释放为驾驭力、把新域翻译为碳硅能力、把闭环放大为意义创造。

**修正后的 Problem**：
> 超级个体知道自己有用AI的能力，但说不清该往哪个方向集中投入。把时间撒在减重复、解锁新域和放大产出上，不如先判断当下投入哪个方向回报最快。

**修正后的关联工具**：
```
超级个体三轴能力自测 → 智能密度三向定位 → 人机链路五步法（把方向落地为具体任务单元）
```

### 2.2 P0-2：管理者新旧价值转变自检

**严重问题**：四组"弱化→增强"对照来自《极简AI领导力》的管理者价值转变图谱，不是碳硅的概念框架。用词"信息枢纽""能力供给者""场域营造者"均非碳硅语。

| 审计项 | 原设计（❌ 外来语） | 修正（✅ 碳硅语） | 理由 |
|:--|:--|:--|:--|
| 工具名 | 管理者新旧价值转变自检 | **大陆管理者→海洋关键角色迁移自检** | 碳硅的核心叙事是"从大陆到海洋"，管理者就是大陆物种中最需要迁移的一类 |
| 四组对照框架 | 弱化价值 vs 增强价值 | **大陆职能 vs 海洋职能**（用结构层/细胞层/环境层的角色变化来组织） | 碳硅分析一切问题的框架是三螺旋，不是"价值强弱" |
| 组1 | 信息枢纽 → 意义赋予者 | **结构层：从"传递信息"转向"定义任务单元的目标和验证标准"** | 结构层=价值围绕什么流动，"任务单元"是结构层的核心 |
| 组2 | 能力供给者 → 异常捕捉者 | **细胞层：从"分配人做任务"转向"配置人机混合智能细胞"** | 细胞层=最小生产单元，"混合智能细胞"是细胞层的核心 |
| 组3 | 标准化管理 → 人机协同设计者 | **碳硅翻译：从"确保人按流程做"转向"设计碳硅协作的接口与边界"** | 碳硅翻译力是管理者最核心的新职能 |
| 组4 | 流程守护者 → 场域营造者 | **环境层：从"看守规则"转向"营造意义/权力/信任的生长条件"** | 环境层=让协作持续发生的条件，"意义/权力/信任"是核心 |
| 评分术语 | 旧价值弱化分/新价值准备度分 | **大陆职能依赖度 / 海洋职能成熟度** | 不做好坏判断，只做迁移进度判断 |
| 行动建议 | "30天转变计划" | "**第一条角色迁移火种**" | 碳硅行动单元是"火种" |

**修正后的四组对照（替换整个评估框架）**：

| 大陆职能（旧范式） | 自评依赖度 | 海洋职能（新范式） | 自评成熟度 |
|:--|:--|:--|:--|
| **结构层**：我花大量时间传递信息、汇总报告、上传下达 | 1-5 | **结构层**：我花时间定义任务单元的边界、目标和验证信号 | 1-5 |
| **细胞层**：我花大量时间分配任务、跟踪进度、协调人手 | 1-5 | **细胞层**：我花时间配置人机混合智能细胞，明确碳硅分工 | 1-5 |
| **碳硅翻译**：我花大量时间确保人按流程做、按SOP执行 | 1-5 | **碳硅翻译**：我花时间设计碳硅协作的接口、验收标准和边界规则 | 1-5 |
| **环境层**：我花大量时间审批、检查合规、看守规则 | 1-5 | **环境层**：我花时间营造意义清晰、权力下放、信任可验证的生长条件 | 1-5 |

**修正后的 Purpose**：
> 大陆管理者之所以累，是因为还在用大陆文明的职能做事。这个工具帮助关键角色看清：自己仍然卡在大陆职能的哪些环节，以及如何把精力迁移到海洋文明真正需要的位置上。

**修正后的 Problem**：
> 很多管理者感到力不从心——不是不努力，是旧大陆赋予的职能（传递信息、分配任务、看守流程）正在被智能层替代，而海洋文明需要的职能（定义任务单元、配置碳硅细胞、设计验证回路、营造意义与信任）还没有被正式承认。

### 2.3 P0-3：AI价值扫描矩阵

**中等问题**：框架本身可用，但用词不碳硅。"矩阵""扫描""Quick Win"都是外来语。

| 审计项 | 原设计（❌ 外来语） | 修正（✅ 碳硅语） | 理由 |
|:--|:--|:--|:--|
| 工具名 | AI价值扫描矩阵 | **任务链路火种优先级诊断** | "火种"是碳硅的核心行动概念；"链路"是观察单位；"诊断"是碳硅工具类型 |
| 双维度名 | 业务影响力 × AI适配度 | **闭环价值密度 × 碳硅就绪度** | "闭环价值密度"=这个链路的业务价值是否可闭环验证；"碳硅就绪度"=数据/规则/验证回路是否可支撑碳硅协作 |
| 象限名 | Quick Win / 规划投入 / 快速放手 / 避免浪费 | 四个碳硅象限：**立即孵化火种 / 补条件再点火 / 低频不投 / 高配低值** | 避免咨询术语 |
| 子维度 | 业务关键度/频率/耗时/满意度 | **闭环必要性**（不跑通这条链路，哪个业务结果无法改善？）+ **可验证性**（信号多快能看见？） | 碳硅以"闭环"和"验证信号"为核心 |
| AI适配子维度 | 规则清晰度/数据可得性/输出可验证性 | **业务本体成熟度**（业务对象、规则、动作是否已被结构化）+ **验证回路是否已有最小闭环** | "业务本体"和"验证回路"是碳硅四支柱的核心概念 |
| 输入要求 | 候选任务/场景列表 | 候选**任务链路**列表 | 统一用"链路" |
| 行动建议 | "第一个试点步骤" | "**火种定义**：链路范围+碳硅分工+两周验证信号" | 用碳硅火种五要素 |

**修正后的 Purpose**：
> 组织不缺AI可以介入的任务——缺的是判断先投哪条链路能最快形成可验证的碳硅闭环。这个工具用闭环价值密度和碳硅就绪度两个维度，帮团队选出第一条值得点火的任务链路。

**修正后的 Problem**：
> 一说到AI，团队能列出二十个场景——但资源分散下去的后果是一条链路都没跑通。不是AI不好用，是缺少一套把候选链路按碳硅逻辑排序的方法。

### 2.4 P1-4：AI Native管理者四角色定位

**中等问题**：四个角色的名字来自《极简AI领导力》的框架。

| 审计项 | 原设计（❌ 外来语） | 修正（✅ 碳硅语） | 理由 |
|:--|:--|:--|:--|
| 工具名 | AI Native管理者四角色定位 | **海洋关键角色四向定位** | 用"海洋"对应"大陆管理者"，用"关键角色"替代"管理者" |
| 角色1 | 工作流设计者 | **任务单元定义者** | 碳硅的"任务单元"概念；不只是画流程图，是定义人+AI+数据+验证的完整单元 |
| 角色2 | AI增强型决策者 | **碳硅判断锚定者** | 核心是定义"人的判断放在哪个节点"，而非泛化"AI辅助决策" |
| 角色3 | 人机混合团队领导者 | **碳硅细胞配置者** | "混合智能细胞"是碳硅核心概念；职责是配置细胞内的角色、接口、护栏 |
| 角色4 | 组织学习架构师 | **业务本体沉淀者** | "业务本体"不是"组织学习"——是把经验结构化让碳硅系统能读懂和复用 |
| 评分术语 | 成熟度 | **角色就绪度** | 保持一致 |

**修正后的四个角色**：

| 角色 | 碳硅定义 | 关键行为信号 |
|:--|:--|:--|
| **任务单元定义者** | 把一个业务闭环配置为可独立运行的人+AI+数据+接口单元 | 能画出谁定义目标、AI执行哪段、人在哪个节点判断、验收信号是什么 |
| **碳硅判断锚定者** | 在碳硅协作链路中，把人类判断力精确放在不可替代的节点上 | 能说清哪些决策是碳硅协作后由人拍板、哪些纯由AI执行、哪些纯由人判断 |
| **碳硅细胞配置者** | 连接多个任务单元和管理它们的接口、护栏、权限和协作节奏 | 能为混合智能细胞定义输入输出标准、风险节点和人工确认边界 |
| **业务本体沉淀者** | 把每次协作中产生的判断规则、验收标准、失败模式结构化，让碳硅系统能持续进化 | 团队有可检索的业务规则库、失败模式库、验收清单——而非依赖个人记忆 |

**修正后的关联工具**：
```
大陆管理者→海洋关键角色迁移自检 → 海洋关键角色四向定位 → 岗位任务单元重写卡
```

### 2.5 P1-5：岗位职责加减乘除卡

**严重问题**：整个框架来自《极简AI领导力》，"加减乘除"是它的标志性记忆法。"岗位"本身是大陆概念。

| 审计项 | 原设计（❌ 外来语） | 修正（✅ 碳硅语） | 理由 |
|:--|:--|:--|:--|
| 工具名 | 岗位职责加减乘除卡 | **岗位→任务单元重写卡** | 碳硅的变革方向不是"优化岗位"，是把"岗位"解构成"任务单元" |
| 加法 | 增强AI时代新职责 | **升维：把碳硅判断嵌入任务单元** | 不是"加职责"，是"把原先散落在岗位里的判断力，显性定义为任务单元的核心节点" |
| 减法 | 剔除重复低价值任务 | **卸载：把可被验证回路覆盖的工作移交给碳硅系统** | 不是"减任务"，是"把有明确验证标准的重复工作移交给AI+验证回路" |
| 乘法 | AI放大个人产出 | **编织：把一个人能闭环的链路编织成可复用的混合智能细胞** | "乘法"是结果描述，"编织"是动作描述。碳硅的"细胞"自带复用属性 |
| 除法 | 剥离不应由人承担的职责 | **解耦：把不属于这个任务单元的依赖、审批和历史包袱拆掉** | "除法"太数学，"解耦"是碳硅组织设计的核心动作 |
| 画布名称 | 四宫格画布 | **四象限任务单元孵化画布** | 与"任务单元孵化卡"形成工具族 |

**修正后的 Purpose**：
> 任务单元的核心假设是：人不是被安排在岗位上，而是被配置进一个能自我闭环的碳硅协作单元里。这个工具把旧大陆的"岗位职责"拆解为四步：卸载（交给验证回路）、升维（嵌入碳硅判断）、编织（连接成细胞）、解耦（剥离大陆遗产）。

**修正后的 Problem**：
> 很多组织嘴上说"岗位要重新定义"，但做的事是在旧JD上增增减减。真正的重写是把"岗位"这个大陆概念拆掉，重新组织成"任务单元"——一个能独立闭环、有明确碳硅分工、可验证、可复用的最小生产单元。

**修正后的关联工具**：
```
任务画像重写卡 → 岗位→任务单元重写卡 → 任务单元孵化卡
    （旧工具）      （新工具）            （旧工具）
```

### 2.6 P1-6：AI原生工作者习惯检视卡

**中等问题**：7个习惯来自《极简AI领导力》，需要翻译为碳硅行为语言。

| 审计项 | 原设计（❌ 外来语） | 修正（✅ 碳硅语） | 理由 |
|:--|:--|:--|:--|
| 工具名 | AI原生工作者习惯检视卡 | **驾驭工程日常检视卡** | "驾驭工程"是碳硅对个人使用AI的核心理念——不是用AI，是设计人+AI的工作环境 |
| 习惯H1 | AI先跑 | **先建回路再动手** | 不是"让AI先跑"，是"先定义一个完整的人机闭环再开始执行" |
| 习惯H2 | 沉淀资产 | **把单次经验结构化** | 碳硅强调"业务本体"——不只是记笔记，是把经验变成碳硅系统能读懂的规则、模板、验收标准 |
| 习惯H3 | 固化工作流 | **把链路写成可复用的细胞模板** | "工作流"太宽泛，"细胞模板"是碳硅的精确概念 |
| 习惯H4 | 人机分工 | **锚定碳硅边界** | 碳硅分工不是"人做什么AI做什么"，是"哪个节点由人判断、哪个节点由验证回路接管" |
| 习惯H5 | 闭环迭代 | **跑验证回路** | 碳硅的闭环有严格定义：设标准→跑→查差距→修→沉淀。不是"迭代"这么泛 |
| 习惯H6 | 主动试错 | **测试碳硅边界** | 不是泛泛"追新"，是"主动用真实任务测试今天的AI能做到哪一步" |
| 习惯H7 | AI思维 | **从执行者迁移到驾驭者** | 碳硅的核心转变不是"用AI思维"，是"从亲手做到设计碳硅协作环境" |

**修正后的 Purpose**：
> 驾驭工程不是一次性学会的，是每天用6个微动作练出来的。这个工具把碳硅超级个体的日常实践变成可检视、可实验的行为框架。

### 2.7 P2-7：人才梯队3:6:1诊断

**严重问题**："3:6:1"是外来数字记忆法。"探索者/重构者/引领者"不是碳硅分类。

| 审计项 | 原设计（❌ 外来语） | 修正（✅ 碳硅语） | 理由 |
|:--|:--|:--|:--|
| 工具名 | 人才梯队3:6:1诊断 | **碳硅人才密度诊断** | "人才密度"是碳硅用的概念；不必用数字命名法 |
| 三类人 | 探索者 / 重构者 / 引领者 | **火种发现者 / 细胞编织者 / 意义锚定者** | 三类碳硅角色：发现链路可跑（火种发现）→ 把人机协作跑成稳定细胞（细胞编织）→ 定义方向、标准和意义（意义锚定） |
| 比例 | 3:6:1 | 不设固定比例，而是诊断**缺失类型** | 碳硅不给数字，给诊断——"你的团队缺少哪类人？" |
| 行为信号 | 4个行为信号 | 用碳硅行为锚：**闭环过什么链路？沉淀了什么资产？定义了哪些碳硅边界？** | 不是泛泛的"用没用AI"，是具体的碳硅产出 |

**修正后的 Purpose**：
> 碳硅组织的人才密度，不看多少人会工具，看团队里是否同时存在三类关键角色：有人能发现可跑的火种链路，有人能把火种编织成稳定复用的细胞，有人能锚定意义和方向。

**修正后的关联工具**：
```
超级个体三轴能力自测 → 碳硅人才密度诊断
```

| 核心论断 | "中层不是被AI消灭" | **"大陆的中间层职能正在被智能层接管，但海洋需要的是另一种角色——从信息路由变成碳硅边界的定义者和验证回路的校准者"** | 用碳硅的"智能层"概念 |

| 接管方式 | 系统接管/AI接管/下放一线/取消不做 | **智能层吸收 / 验证回路覆盖 / 火种团队自决 / 随大陆层级一起退化** | 用碳硅语言 |

### 2.9 P2-9：90天团队AI转型计划模板

**中等问题**："培训→工具应用→成果固化"是传统转型语言，不是碳硅的变革逻辑。

| 审计项 | 原设计（❌ 外来语） | 修正（✅ 碳硅语） | 理由 |
|:--|:--|:--|:--|
| 工具名 | 90天团队AI转型计划模板 | **90天火种→细胞→回路 团队进化计划** | 碳硅90天三段论：先点火种、再编细胞、最后形成复用的验证回路 |
| 阶段1 | AI认知与培训 | **共识+火种发现**（统一碳硅语言 + 用链路诊断找到第一条可跑的火种） | 不培训"工具使用"，而是"共识碳硅语言"+"找出第一条链路" |
| 阶段2 | AI工具应用实践 | **火种孵化+细胞编织**（选1条链路跑通→沉淀碳硅分工→做成可复用的细胞模板） | 不只"用起来"，是"跑成细胞" |
| 阶段3 | 成果固化与创新 | **回路验证+组织沉淀**（多轮复跑→验证信号收集→经验结构化→进入下一链路） | 不只是"总结表彰"，是形成可自我进化的验证回路 |
| 里程碑用语 | 效果评估/成果固化 | **验证信号出现 / 细胞可复用 / 回路自运转** | 碳硅的里程碑不是"完成了什么文档"，是"出现了什么信号" |

**修正后的三个阶段**：

| 阶段 | 碳硅名称 | 核心动作 | 验证信号 |
|:--|:--|:--|:--|
| 前30天 | **共识与火种** | 统一碳硅语言 → 链路优先级诊断 → 选定第一条火种链路 → 定义碳硅分工 | 至少1条链路的火种定义完成 |
| 中间30天 | **孵化与编织** | 火种试跑 → 收集验证信号 → 修正碳硅接口 → 沉淀为可复用的细胞模板 | 火种链路跑出第一轮验证信号 |
| 后30天 | **回路与沉淀** | 多轮复跑 → 业务本体沉淀 → 验证回路固化 → 启动第二条链路 | 第一条链路的验证回路可脱离个人运转 |

## 四、审计结论

### 修复统计

| 严重程度 | 数量 | 涉及工具 |
|:--|:--|:--|
| 🔴 严重（框架来自外来体系） | 3个 | P0-1（减加乘）、P1-5（加减乘除）、P2-7（3:6:1） |
| 🟡 中等（用词不碳硅） | 5个 | P0-2、P0-3、P1-4、P1-6、P2-9 |
| 🟢 轻微 | 1个 | P2-8 |

### 核心修正原则（之后所有工具设计都应遵守）

1. **不引入非碳硅的记忆框架**（如减加乘、3:6:1）
2. **用三螺旋作为一切诊断的底层结构**（结构层/细胞层/环境层）
3. **用"火种→细胞→回路"作为行动递进逻辑**
4. **用"任务单元""碳硅翻译""业务本体""验证回路"作为核心操作概念**
5. **用"大陆→海洋"作为叙事轴线**，所有"旧→新"的对照都锚定在这个隐喻上
6. **命名用碳硅动词**：定位/迁移/诊断/重写/孵化/编织/沉淀/解耦——而不是扫描/评估/优化/管理
