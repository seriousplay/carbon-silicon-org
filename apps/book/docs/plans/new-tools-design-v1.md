1. **每个工具都有独立价值**：单人可用，不依赖引导师，10-30分钟可完成

4. **字段设计遵循 tool-products.json schema**：可直接导入

## 🟢 P0-1：AI价值三路径定位卡

### 基础信息

```yaml
id: "ai-value-three-paths"
chapter: 7
name: "AI价值三路径定位卡"
subtitle: "你的工作中藏着多少减法、加法、乘法的机会？"
purpose: "帮助参与者从减/加/乘三条路径审视自己的工作，识别第一条可行动的价值重构链路。"
output: "个人三路径雷达图 + 3个优先行动场景 + 第一条行动承诺"
tags: ["超级个体", "价值重构", "减法加法乘法", "行动规划"]
toolType: "assessment"
scenarioTags: ["核心测评", "AI 试点落地"]
targetUsers: ["管理者", "HR/OD一号位", "超级个体"]
duration: "20-30分钟"
participants: "1人（个人自评）"
onlineSupport: "assessment"
problem: "管理者知道'AI应该创造价值'，但说不清自己的工作中到底哪些可以做减法（提效）、哪些可以做加法（解锁新能力）、哪些可以做乘法（放大产出）。"
whenToUse:
  - "工作坊中「超级个体」模块开始前，作为前置自评"
  - "个人制定AI学习路径时，识别从哪条路径切入最快"
  - "团队AI转型启动时，统一对「价值」的认知框架"
notFor:
  - "组织层面的AI战略选择（请用「行业AI路径三问」）"
  - "已经明确知道要做什么的人"
inputs:
  - "参与者当前岗位/角色描述"
  - "每周花时间最多的5-8项工作任务"
  - "每项任务的大致耗时和频率"
```

### 测评表单设计

**表单字段（formFields）：**

| 字段 | 类型 | 说明 |
|:--|:--|:--|
| `role` | 自由文本 | 当前岗位/角色 |
| `tasks` | 动态表单（5-8项） | 每项含：任务名称、耗时(小时/周)、频率(天/周/月) |
| `subtraction_checklist` | 多选（4项） | 减法自检清单 |
| `addition_checklist` | 多选（4项） | 加法自检清单 |
| `multiplication_checklist` | 多选（4项） | 乘法自检清单 |
| `priority_path` | 单选 | 你最想先走哪条路？ |
| `first_action` | 自由文本 | 本周就做的一个动作 |

**减法自检清单（subtraction_checklist）：**

| 编号 | 问题 | 是/否 |
|:--|:--|:--|
| S1 | 我每周花在「重复性劳动」上的时间超过10小时 | □ |
| S2 | 我的工作中有步骤基本固定、规则清晰的任务 | □ |
| S3 | AI产出的质量可以被明确验证或检查 | □ |
| S4 | 如果省下这些时间，我有更高价值的事可做 | □ |

> 如果S1-S4全部为「是」→ 减法优先级最高

**加法自检清单（addition_checklist）：**

| 编号 | 问题 | 是/否 |
|:--|:--|:--|
| A1 | 我一直想学但没时间学的技能，AI可以帮我弥补 | □ |
| A2 | 有业务机会因为我缺少某种能力而放弃了 | □ |
| A3 | 有了AI辅助，我可以服务的客户/场景会明显扩大 | □ |
| A4 | 我不需要成为专家，只需要「能判断AI产出好坏」就够了 | □ |

> 如果A1-A4全部为「是」→ 加法优先级最高

**乘法自检清单（multiplication_checklist）：**

| 编号 | 问题 | 是/否 |
|:--|:--|:--|
| M1 | 我的产出受限于「人力瓶颈」，而非需求不足 | □ |
| M2 | 如果有AI做80%执行，我能放大至少3倍产出 | □ |
| M3 | 我当前在做的事，很大程度上是「机器该做的事」 | □ |
| M4 | 我准备好从「执行者」转型为「设计者/编排者」 | □ |

> 如果M1-M4全部为「是」→ 乘法优先级最高

### 评分与报告

**评分规则（scoring）：**

```
每个路径得分 = 对应checklist中「是」的数量（0-4分）

解读：
- 某路径得分4 → 高优先级（该路径有明确可行动场景）
- 某路径得分2-3 → 中优先级（有条件但需进一步验证）
- 某路径得分0-1 → 低优先级（条件不成熟或不需要）
```

**报告结构（reportBlocks）：**

1. **三路径雷达图**：减/加/乘三轴得分可视化
2. **最强路径推荐**：得分最高的路径 + 对应的具体场景建议
3. **弱区提示**：得分最低路径的意义（比如减法分低可能意味着你已经在做高价值工作）
4. **「但书」提醒**：
   - 减法分高 ≠ 你的工作没价值 → 是你把时间花在了可自动化的事上
   - 乘法分高 ≠ 你应该立刻放大 → 先确认AI能稳定完成80%
5. **第一条行动**：基于最强路径的1条本周可启动的动作

**报告示例：**

```
┌─────────────────────────────────────┐
│  AI价值三路径定位报告                  │
│                                      │
│  减法 ████████░░ 2/4  中              │
│  加法 ████████████ 4/4  高 ⭐         │
│  乘法 ██████░░░░ 1/4  低              │
│                                      │
│  推荐路径：加法                        │
│  → 你一直想做但因为缺能力而搁置的事，   │
│    AI可以帮你打开。                     │
│                                      │
│  本周行动：                            │
│  选一项你「一直想做但没做」的事，       │
│  用AI工具先跑一个初版，看看边界在哪。    │
└─────────────────────────────────────┘
```

### 引导师提示

- 强调：三路径不是互斥的，但建议先集中精力走通一条
- 对于「三路径都是低分」的人：可能他们的工作本身不适合AI深度介入，这是正常结论
- 避免让减法分高的人产生「我的工作没价值」的焦虑——强调减法释放的时间用于更高价值的事

### 常见误区

- 把「用AI写周报」归为减法中的高价值——周报本身可能是低价值任务
- 对乘法的理解停留在「多做几倍」而忽视了「做不同的事」
- 跳过自检清单直接选路径——自检清单的设计是为了暴露盲区

### 关联工具

```
- 超级个体三轴能力自测 → 做完三轴后来做路径定位
- AI价值扫描矩阵 → 选定路径后，用扫描矩阵筛选具体场景
- 人机链路五步法 → 选定场景后，用五步法设计链路
```

## 🟢 P0-2：管理者新旧价值转变自检

### 基础信息

```yaml
id: "manager-value-shift-check"
chapter: 9
name: "管理者新旧价值转变自检"
subtitle: "AI正在废掉你的哪些旧价值？又在召唤哪些新价值？"
purpose: "帮助管理者识别AI时代自己价值结构的真实变化，定位「被弱化」的职能和「被增强」的新机会。"
output: "新旧价值对比图 + 最需升级的2项能力 + 30天转变计划"
tags: ["管理者", "角色转变", "价值重构", "领导力升级"]
toolType: "assessment"
scenarioTags: ["核心测评", "领导力发展"]
targetUsers: ["管理者", "HR/OD一号位"]
duration: "25-35分钟"
participants: "1人（个人自评）"
onlineSupport: "assessment"
problem: "管理者感受到旧职能在贬值（信息传递、任务分配、进度监督），但不知道新价值在哪里聚焦（意义赋予、异常捕捉、人机协同设计、场域营造）。结果是既焦虑又茫然。"
whenToUse:
  - "工作坊中「领导力」模块，作为前置自评"
  - "管理层AI转型启动会前，统一认知"
  - "个人职业发展规划，识别AI时代的差异化价值"
notFor:
  - "非管理岗位"
  - "已经完成角色转型的AI Native管理者"
inputs:
  - "管理者当前的团队规模和管理层级"
  - "典型一周的时间分配（按活动类型）"
  - "过去3个月最花精力的5件事"
```

### 测评表单设计

**核心评估框架：四组新旧价值对照**

每组包含一个「旧价值」（正在被弱化）和一个「新价值」（正在被增强），参与者需要分别自评。

**评估维度：**

| 旧价值（正在弱化） | 弱化程度自评 | 新价值（正在增强） | 增强准备度自评 |
|:--|:--|:--|:--|
| **信息枢纽**：上传下达、汇总数据、汇报进展 | 1-5分 | **意义赋予者**：描绘愿景、价值判断、让团队理解「为什么」 | 1-5分 |
| **标准化管理**：分解任务、分配任务、跟踪进度 | 1-5分 | **异常捕捉者**：从数据中嗅到信号、感知团队士气、捕捉潜在需求 | 1-5分 |
| **能力供给者**：培训员工、调配资源、推荐路径 | 1-5分 | **人机协同设计者**：设计协作流程、帮助团队理解AI边界、持续优化AI | 1-5分 |
| **流程守护者**：确保SOP执行、审批把关、合规检查 | 1-5分 | **场域营造者**：建立价值判断规则、营造信任透明、警惕AI边界 | 1-5分 |

**补充自评问题：**

| 编号 | 问题 | 类型 |
|:--|:--|:--|
| Q1 | 你一周花在「传递信息、汇报进展」上的时间占多少？ | 单选：<20% / 20-40% / 40-60% / >60% |
| Q2 | 团队中是否已经有人在用AI自动完成你过去手动做的事？ | 是/否/不确定 |
| Q3 | 你上一次跟团队讲「为什么做这件事」，而不是「怎么做这件事」是什么时候？ | 单选：本周/本月/上个月/记不清了 |
| Q4 | 如果AI能接手你80%的流程管理工作，你会把时间用来做什么？ | 自由文本 |

### 评分与报告

**评分规则：**

```
旧价值总弱化分 = 四项旧价值自评分之和（4-20分）
新价值准备度分 = 四项新价值自评分之和（4-20分）
转变差距 = 新价值准备度分 - 旧价值总弱化分

解读：
- 转变差距 > 4 → 「新价值已开始形成，旧角色在松动」✅
- 转变差距 0~4 → 「正在过渡期，新旧交替中」⚠️
- 转变差距 < 0 → 「旧价值还在主导，新价值尚未形成」❌ 高优先级
```

**报告结构：**

1. **转变差距总分** + 趋势解读
2. **四组雷达图**：旧价值弱化 vs 新价值准备度并排对比
3. **最强旧价值**：得分最高的旧价值（最需要主动放手的部分）
4. **最弱新价值**：得分最低的新价值（最需要刻意建设的部分）
5. **关键追问**（基于Q1-Q4的定性反馈）：
   - 时间分配是否已经开始转移？
   - 团队是否已经在「用脚投票」？
6. **30天转变计划**：聚焦最弱新价值的1个刻意练习

**报告示例：**

```
┌──────────────────────────────────────────┐
│  管理者新旧价值转变自检报告                  │
│                                           │
│  旧价值总弱化：14/20  ██████████░░░░ 高     │
│  新价值准备度：8/20   ██████░░░░░░░░ 低     │
│  转变差距：-6  ❌ 旧价值还在主导              │
│                                           │
│  ⚠️ 你花在「信息传递」和「流程守护」上的     │
│  时间太多了。你的团队可能已经在想：           │
│  「这些事AI就能做，老板在干什么？」          │
│                                           │
│  最需要放手的：信息枢纽（5/5弱化）            │
│  → 别再当人肉路由器了。让AI拉数据、写报告。   │
│                                           │
│  最需要建设的：人机协同设计者（1/5准备度）     │
│  → 这是管理者在AI时代最稀缺的能力。           │
│                                           │
│  30天行动：                                  │
│  选一个团队高频任务，设计第一版人机协作SOP，   │
│  标注「AI做→人判断→人拍板」的节点。           │
└──────────────────────────────────────────┘
```

### 引导师提示

- 强调这不是「旧价值不好新价值好」的评判——旧价值在特定场景仍然重要
- 如果参与者旧价值得分很低但团队运行正常 → 可能已经是AI Native管理者
- 对于转变差距为负的管理者：第一件事不是学新技能，是停止做旧的事
- Q4是定性锚点——如果参与者说不清「省下的时间用来做什么」，意味着认知缺口

### 常见误区

- 误以为「意义赋予者」就是多给团队讲鸡汤——本质是把战略翻译为团队语言
- 把「人机协同设计者」理解为IT技能——本质是业务理解+边界判断
- 旧价值得分高不等于「我是个坏管理者」——可能只是组织还没有系统化替代方案

### 关联工具

```
- AI Native管理者四角色定位 → 做完转变自检后，用四角色定位工具细化
- 园丁型领导力注意力自查 → 互补视角
- 中层重塑画布 → 如果需要从岗位层面重新定义
```

## 🟢 P0-3：AI价值扫描矩阵

### 基础信息

```yaml
id: "ai-value-scan-matrix"
chapter: 8
name: "AI价值扫描矩阵"
subtitle: "不是所有任务都值得用AI——先扫描，再投入。"
purpose: "帮助团队或个人从众多任务中筛选出AI介入回报最高的场景，优先投入Quick Win。"
output: "任务扫描清单 + 双维度四象限矩阵 + Top 3优先场景"
tags: ["人机链路", "场景筛选", "优先级", "AI试点"]
toolType: "diagnosis"
scenarioTags: ["AI 试点落地", "工作坊主工具"]
targetUsers: ["管理者", "超级个体", "HR/OD一号位"]
duration: "30-45分钟"
participants: "1-5人"
onlineSupport: "assessment"
problem: "团队看到AI的各种可能性，但不知道该从哪个任务开始。结果要么「全面铺开」导致资源分散，要么「等等再看」错过时机。"
whenToUse:
  - "启动AI试点之前，作为场景筛选的标准流程"
  - "人机链路五步法之前，先选定要重构的具体链路"
  - "多个AI项目在竞争资源时，作为优先级排序工具"
notFor:
  - "已经明确知道要做什么只是需要执行方案时"
  - "战略级AI转型方向选择（请用行业AI路径三问）"
inputs:
  - "候选任务/场景列表（5-15个）"
  - "每个任务的基本信息：名称、频率、当前耗时、涉及角色"
```

### 测评表单设计

**Step 1：任务录入**

参与者先列出工作/团队中的候选任务（5-15个），对每个任务填写：

| 字段 | 说明 | 示例 |
|:--|:--|:--|
| 任务名称 | 简短命名 | 「每周销售数据报告」 |
| 当前耗时 | 每周花多少小时 | 8小时 |
| 频率 | 天/周/月/季 | 周 |
| 涉及人数 | 直接和间接 | 3人 |
| 当前痛点 | 最让人烦的是什么 | 「数据来自3个系统，手动合并」 |

**Step 2：双维度评分**

对每个任务进行两个维度的1-5分评估：

**维度一：业务价值（Y轴）**

| 子维度 | 1分 | 3分 | 5分 |
|:--|:--|:--|:--|
| 耗时占比 | <1h/周 | 3-5h/周 | >10h/周 |
| 频率 | 季/年 | 周 | 天 |
| 业务关键度 | 锦上添花 | 重要但非核心 | 直接影响收入/客户 |
| 当前满意度 | 还行 | 经常出问题 | 痛点明确，每次都想逃避 |

> 业务价值分 = 四子维度平均分（取整）

**维度二：AI适配度（X轴）**

| 子维度 | 1分 | 3分 | 5分 |
|:--|:--|:--|:--|
| 规则清晰度 | 高度依赖经验和判断 | 有模糊规则 | 流程步骤明确，逻辑清晰 |
| 数据可得性 | 数据分散、难以获取 | 有数据但需清理 | 数据结构化、API可调 |
| 输出可验证性 | 输出质量主观 | 部分可量化 | 有明确的正确/错误标准 |
| 风险可控性 | 出错后果严重 | 有人工复核机制 | 错误影响小，可快速修正 |

> AI适配度分 = 四子维度平均分（取整）

**Step 3：矩阵定位**

将每个任务按（AI适配度, 业务价值）定位到四象限：

```
        高业务价值
            │
  规划投入   │   ⭐立即行动
  (高价值    │  (高价值
   低适配)   │   高适配)
            │
────────────┼──────────── AI适配度 →
            │
  快速放手   │   避免浪费
  (低价值    │  (低价值
   低适配)   │   高适配)
            │
        低业务价值
```

### 评分与报告

**报告结构：**

1. **任务扫描总览表**：所有任务的评分和象限分布
2. **四象限矩阵图**：可视化显示每个任务的位置
3. **Quick Win推荐**：落在「立即行动」象限的Top 3任务
4. **每个Quick Win的卡片**：
   - 当前状态（耗时、痛点、涉众）
   - AI可能性评估（哪些子任务可被AI接手）
   - 预期收益（预计节省时间、质量改善）
   - 第一个试点步骤
5. **避坑提醒**：
   - 「避免浪费」象限的任务——虽然AI能做，但做了不值得
   - 「规划投入」象限的任务——有价值但条件不成熟，别急着上

### 引导师提示

- 如果团队第一次用，先引导做一个例子再放手让他们自己填
- 对「业务价值」的评分往往会偏高——提醒：如果一个任务每周只花1小时，无论多痛都未必是高价值
- 关注评分分歧：如果同一任务不同人评分差异 > 2分 → 认知没对齐，先讨论
- 理想结果：找到1-3个Quick Win，而不是撒网10个

### 常见误区

- 把所有任务都往「立即行动」象限放——做减法，最多选3个
- AI适配度只看「AI能不能做」不看「做的成本」——数据准备才是大头
- 忽视「规划投入」象限——那不是放弃，是等条件成熟的时候再启动

   - 样板先锋（能跑通真实任务）→ 让TA带小组
   - 炫技区（会工具但不交付）→ 用交付标准校准
4. **人才发展建议**：
   - 如何从执行者→探索者（给工具+给场景）
   - 如何从探索者→重构者（给真实项目+要求沉淀）
   - 如何从重构者→引领者（给创新空间+成果激励）

```yaml
name: "中层重塑画布"
subtitle: "中层不是被AI消灭——是被AI拆解后重新组装。"
purpose: "系统化拆解中层管理的5项传统职能，判断哪些被AI接管，哪些升级为更高价值。"
output: "中层职能拆解图 + 新旧职能对照 + 个人重塑路线图"
tags: ["中层管理", "职能拆分", "角色重塑", "组织设计"]
toolType: "template"
scenarioTags: ["组织诊断", "领导力发展"]
targetUsers: ["中层管理者", "HR/OD一号位", "CEO"]
duration: "45-60分钟"
participants: "1-3人"
onlineSupport: "template"
problem: "中层管理是组织中被冲击最直接也最迷茫的层级。旧职能（信息路由、进度监督、资源协调）正在被系统替代，但新职能（判断放大、能力发展、边界定义）还没有被正式定义。"
whenToUse:
  - "组织层级压缩时，重新定义中层角色"
  - "中层管理者个人发展对话时"
  - "组织架构调整后的角色定义工作"
notFor:
  - "高层战略决策"
inputs:
  - "当前中层岗位JD"
  - "过去一周的时间分配"
```

### 画布结构

一页A3画布，左右对照：

```
┌──────────────────────────┬──────────────────────────┐
│  旧中层：信息路由器         │  新管理：人与判断的放大器    │
│                            │                            │
│  ┌──────────────────────┐ │  ┌──────────────────────┐ │
│  │ ① 收集信息    → [接管] │ │  │ → 培养人             │ │
│  │ ② 上传下达    → [接管] │ │  │ → 把关关键判断        │ │
│  │ ③ 协调资源    → [接管] │ │  │ → 解决异常            │ │
│  │ ④ 主持对齐    → [接管] │ │  │ → 定义边界            │ │
│  │ ⑤ 监督进度    → [接管] │ │  │ → 贴近客户与现场      │ │
│  └──────────────────────┘ │  └──────────────────────┘ │
│                            │                            │
│  接管方式：                 │  新价值公式：              │
│  [系统接管] [AI接管]        │  「我不是掌握信息的人，     │
│  [下放一线] [取消不做]      │   我是让人和系统做出更好    │
│                            │   判断的人」               │
└──────────────────────────┴──────────────────────────┘
```

### 使用步骤

1. **列出旧职能**：写出你当前花时间最多的5项职能
2. **判断接管方式**：每项职能标注——系统接管 / AI接管 / 下放一线 / 取消不做
3. **定义新职能**：从培养人、把关判断、解决异常、定义边界、贴近现场五个方向，各填写1-2项具体行动
4. **时间重分配**：旧职能释放的时间，打算怎么重新分配？
5. **第一周实验**：这周就停做一件事（旧职能），加做一件事（新职能）

### 产出

| 产出物 | 说明 |
|:--|:--|
| 职能拆解图 | 旧5项的接管方式+新5项的具体定义 |
| 时间重分配表 | 旧时间分配 → 新时间分配 |
| 个人重塑路线图 | 30天/60天/90天三阶段计划 |
| 需要上级支持的事项 | 哪些改变需要上级授权或系统性支持 |
